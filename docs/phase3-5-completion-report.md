## 2. 実装内容

### 2.1 フェーズ3（前半）: カレンダー・予定・タスク・アラート（PR #12、`20261103000001`）

- 表 `events`（説明会・インターン・OB/OG訪問・その他。終日か時刻あり）と `tasks`（期日は任意、優先度 1〜3）。企業との紐付けは任意で、`(company_id, user_id)` の複合外部キー
- ビュー `calendar_items`（`security_invoker = true`）。ステップの締切・実施日時・結果通知予定、予定、期日のあるタスクを1つにまとめる。ゴミ箱の企業の項目は除く。編集は元の行を直接更新する（02 §3.6）
- 画面: カレンダー（月・これから30日・タスク）、予定とタスクの追加・編集・削除・完了（チェックはすぐ反映）、ステップの「提出した／受けた」をカレンダーからも、企業詳細の「予定・タスク」欄
- ホーム: 要対応（期限超過・3日以内の締切・結果通知予定日の超過）、直近7日の予定、優先タスク（優先度「高」）
- 予定・タスクの変更はトリガーが履歴に記録する

### 2.2 フェーズ4: 分析・CSV・バックアップと復元・初回設定（PR #13、`20261103000002`）

- 分析: 概要、ステップ別の通過率（分母は通過＋不合格。分母0は「データなし」、B-4）、月別の活動、志望度別、応募区分別、選考終了の理由。グラフは1系列の横棒と表（設計 D9 の Recharts は使っていない。§6）
- CSV: 企業一覧・選考ステップ。BOM 付き UTF-8、日時は JST、先頭が `= + - @` のセルに `'` を付ける
- バックアップ: `export_my_data()`（invoker）。ブラウザでチェックサム（SHA-256）を付けて保存
- 復元: ブラウザで検証（形式・版・所有者・チェックサム・参照・重複）→ 件数のプレビュー → 今のデータの保存 → 「復元する」と入力 → `restore_my_data(jsonb)`。本体は private の definer で、検証・削除・ID の振り直し・挿入・履歴の復元を1トランザクションで行う。所有者が違うバックアップは拒否（D-05）
- 初回設定（表示名・卒業予定年・利用目的、すべて任意、スキップ可）、その他 → プロフィール

### 2.3 フェーズ5: PWA とアイコン（この PR）

- アイコンの確定（「始点 → 分岐 → ゴール」の1本線）。PNG 192・512、Android の丸型用（maskable）、iPhone のホーム画面用、ブラウザのタブ用
- Service Worker（vite-plugin-pwa、02 D10）。画面のファイルだけをキャッシュし、Supabase との通信（就活データ）はキャッシュしない。新しい版が出たら「更新する」を押したときだけ切り替える（入力中の内容を消さないため）
- `sw.js` はブラウザにキャッシュさせない（`vercel.json`）

## 4. 持ち主が行う確認（本番）

### 4.1 Google ログインは「テスト中」のまま使う（2026-11-04 に方針を変更）

当初は OAuth 同意画面を「本番」に切り替える予定だったが、持ち主が試したところ「アプリを公開」が押せなかった。Google の説明では、外部向けのアプリを本番に公開するには、ブランディングの「アプリのドメイン」のリンク（ホームページ・プライバシーポリシー・利用規約）が必須で、JobTrack にはこれらのページがない。

一方、openid・email・profile だけを求めるアプリは、「テスト中」でもテストユーザーの登録が不要で、警告の画面も出ず、7日での期限切れもない（Google の説明）。そこで次の方針にする。

- 公開ステータスは「テスト中」のまま。持ち主はこれまで通り使える
- 2人目を招待するときは、JobTrack の招待管理に加えて、Google Cloud の「対象」→「テストユーザー」にもその人の Gmail を追加する（確実にログインできるようにするため。上限100人）
- ロゴはアップロードしない（アップロードすると、本番では確認（審査）が必要になる）
- アプリ名・ユーザーサポートメール・デベロッパーの連絡先は、2026-11-04 に持ち主が設定済み
- 本番への切り替えは、独自ドメインを買ってホームページ・プライバシーポリシー・利用規約のページを用意するときに改めて判断する（メール通知のドメインの判断と一緒に）

## 5. メール通知（後回しにしたもの）

- 設計（02 §5）: pg_cron（毎時）→ Edge Function → 配信サービス（推奨 Resend）。1日1通のまとめ、重複防止、停止リンク、送信先の確認
- 後回しの理由: Resend の無料プランは、独自ドメインを確認しないと、アカウントを作った本人のアドレスにしか送れない。2人目に届けるにはドメイン（年数百〜2,000円ほど）が必要で、0円運用の例外になる
- 決めること: 2人目を招待するときに、ドメインを買うか、本人あてだけで作るか、ほかの方法にするか
- 通知設定の表（`notification_settings`）はフェーズ1で作成済み。画面と送信の仕組みが未着手
